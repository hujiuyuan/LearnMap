# 知图 LearnMap

把任何一本书变成一张可学习的知识地图，按学习者选择的学习方式生成学习计划，用测试数据持续更新学习者画像，并告诉他下一步学什么、怎么学。

产品方案见项目文件 `product-design/learnmap-product-design-v2.md`。当前在做 **Phase 1a 核心闭环**：书 → 图谱 → 诊断 → 5 种学习方式 → 计划 → 画像 → 辅导者 Dashboard，分多个 PR 逐步交付。

## 目录

| 目录 | 内容 |
|---|---|
| `backend/` | Spring Boot 3 / Java 21 模块化单体，MySQL 8（本地开发可用内存 H2），Flyway 管理表结构 |
| `frontend/` | uni-app（Vue 3），H5 / 微信小程序 / App 一套代码 |

后端按业务分包：`user`（角色、辅导者绑定）、`book`（导入、目录解析、原文块）、`graph`（书本图谱、学习者副本、修正）、`question`（题库、一题多解）、`evidence`（作答 → 证据）、`mastery`（掌握度规则引擎）、`diagnostic`（入门诊断）、`card`（复习卡片 + FSRS）、`practice`（刻意 / 交错 / 第一性原理）、`feynman`、`retest`（延时复测）、`plan`（学习目标、计划、番茄钟）、`profile`（五张画像）、`flag`（辅导者 / 系统对节点的标记）、`tutor`（辅导者 Dashboard）、`ai`（AI 提供方接口）。

## 本地运行

需要 JDK 21、Maven 3.9、Node 18+。

```bash
# 后端：默认 dev 模式，用内存数据库，启动时自动导入演示账号和一本示例书
cd backend
mvn spring-boot:run

# 前端：H5 开发模式，/api 自动转发到 localhost:8080
cd frontend
npm install
npm run dev:h5
```

打开 http://localhost:5173 ，点“学习者 小明” → 打开示例书 → 做入门诊断，看诊断报告 → 回到知识地图看点亮情况；首页的“今日复习”可以翻卡片。

演示账号（仅 dev 模式）：`ops` / `tutor`（王老师）/ `learner`（小明），密码都是 `demo123`，登录页上有一键登录按钮。

正式部署：`learnmap.auth.allow-user-id-header` 默认是 `false`，接口只认登录令牌（`Authorization: Bearer …`）。第一个运维账号通过环境变量 `LEARNMAP_ADMIN_PASSWORD` 创建（用户名 `admin`），不设就不建。dev / test 模式额外允许用请求头 `X-User-Id` 指定当前用户，方便接口测试。

使用 MySQL：

```bash
docker compose up -d mysql
cd backend && mvn spring-boot:run -Dspring-boot.run.profiles=mysql
```

测试：`cd backend && mvn verify`。

## 现在能跑什么、什么还是占位

**已经能跑**
- 三种角色（学习者 / 辅导者 / 运维），辅导者绑定名下学习者，书的可见范围按方案 2.5 执行
- 账号：用户名 + 密码注册（学习者或辅导者）和登录，令牌 30 天有效，可退出；运维账号只能由运维创建
- 上传书：TXT / Markdown、EPUB（按目录顺序，h1–h3 当标题）、Word .docx（“标题 1/2/3”样式当标题）、PDF（有文字层直接取文字，没有就当扫描版逐页 OCR），也可以一次传多张拍照的书页或一个图片 zip，按顺序 OCR 后拼成一本书。按标题解析出 章 → 节 → 小节，切原文块，生成书本图谱和题目
- 校对规则：学习者上传的直接发布（标“未校对”）；辅导者 / 运维可以选“先校对再发布”
- 每个学习者一份图谱副本，互不影响；学习者可以删节点、标记“这条前置关系不对”
- 作答 → 证据 → 掌握度：一题多解按实际用的解法记分，分步作答只扣出错那一步的知识点；未校对节点 Confidence 上限 0.6
- 入门诊断三轮：广度扫描（全书均匀抽 ≤20 题）→ 定向诊断（从错题沿前置往下找 ≤3 层、≤15 题）→ 验证（对疑似根因再出一题，≤10 题）；报告分“疑似根因 / 受前置影响 / 建议再观察 / 已经会了”，根因按影响的后续知识点数排序
- 间隔重复 + 主动回忆：分配书时每个节点自动生成一张卡片，翻面后自评“忘了 / 困难 / 记得 / 轻松”，用 FSRS-4.5 默认参数排下次复习；每次复习都写成证据
- 费曼讲解：打字或拍手写讲解（照片走 OCR），AI 对照要点给出讲到 / 讲漏 / 讲错和追问，可以接着回答追问；低分或有错误陈述的交辅导者复核
- 刻意练习：根因节点先出 3 道验证题，没全对就做 5 道专项练习（含掌握度低的前置），3 天后复验
- 交错练习：至少 3 个掌握度 ≥ 50% 的节点才开始，优先混易混淆的节点，其次同章同类型，8 道打乱顺序，统计“方法选错”
- 第一性原理：选一个目标知识点，数据不足的先探测，不会的沿前置递归往下拆（最多 4 层、超过 15 个提示离基础较远，共享前置只查一次，遇到环停下），再从最底层往上逐个“讲解 + 3 道题”补回来，两轮不过标记给辅导者，最后回到目标做 2 道题
- 延时复测：学会的节点自动安排 3 / 7 / 21 天复测，记下当时用的学习方式
- 学习目标与计划：学习者或辅导者设目标（整本书 / 指定章 / 只补薄弱点、截止日期、工作日和周末各多少分钟、主风格、节奏）。计划先放到期卡片和复测，再按前置关系拓扑排序、薄弱且影响面大的先学，按节点类型 × 主风格配活动（事实：初学 + 小测；概念 / 原理：费曼 + 小测；方法：刻意练习；综合：第一性原理），每 3 天插一次交错练习，每项都写明理由；按番茄钟 25 分钟 / 碎片 10 分钟 / 整块切块；只排 14 天，学不完会提示。每天凌晨 3 点按最新掌握度重排，也能手动重排，做过的任务保留
- 番茄钟：前端计时，开始 / 结束 / 是否坚持完 / 被打断几次记到后端，供行为画像使用
- 五张画像（规则 + 统计，不用 AI）：知识（每章每个节点的掌握度，热力格子）、能力（按题目标注的能力算正确率，费曼平均分算“表达”，答前自评和实际对错的偏差，常用解法）、错误（各错因占比）、学习方式（回放掌握度引擎算每种方式在每类节点上“每 10 分钟提升多少”，加上延时复测保持率和完成率，给出“概念类你用费曼效果最好”这类建议）、学习行为（连续天数、计划完成率、拖延、番茄钟坚持率和打断次数、常学时段）。学习者自己只看点亮数、连续天数和最适合的方式
- 辅导者 Dashboard：名下学习者一览（点亮数、薄弱数、连续天数、计划完成率、提醒）；点进去看五张画像；点任意节点看“为什么不会”——最近作答、前置链上每层的掌握情况、最可能的根因；可以标“诊断不对，他其实会”（马上安排一次复测验证）或“确实不会”；复核低分的费曼讲解（复核分也记成证据）；第一性原理补了两轮还卡住的节点自动提醒辅导者；可以给学习者分配书、设学习目标、看计划
- 运维：汇总被标“诊断不对”最多的书本图谱节点，用来发现题目或图谱的问题
- 班级热力图：辅导者名下学习者 × 章的平均掌握度
- 图谱编辑器（运维、上传书的辅导者）：逐个确认 / 驳回 / 修改 AI 生成的节点和关系，看每条关系的原文证据和节点的原文出处，手动加节点（自动出题）和前置关系，校对完发布为“已校对”
- 同一本书生成了新版本（重新生成，或在编辑器里改了已发布的图谱）：不自动覆盖学习者的副本。系统列出新增 / 删除 / 改动的节点和关系，由人选“合并 / 保留旧版 / 换成新版”——学习者自己上传的书由学习者选，分配下来的书由辅导者选。有学习记录的节点不改不删，学习者自己删掉的节点和标记有误的关系保持原样，新节点自动补复习卡片，旧版题目照样能答
- 节点详情显示原文出处和前置 / 后续
- 记忆宫殿（引导式搭建）：先跟着一座示例宫殿体验一遍；再选一个熟悉的地方，按走动顺序定 5–30 个地点（地点太少、重名、方向乱会提示）；顺着背、倒着背、连续 3 次答对“某地点的下一个”才算建成；每个地点挂一个知识点或自己写的内容，AI 建议夸张画面、可以改成自己的；闭眼走一遍逐个回忆，结果记成证据，并按 FSRS 排下次重走的时间；宫殿可以清空内容留着下次用
- 笔记挂在知识点上：康奈尔笔记（线索栏每行自动变成一张复习卡片，总结栏可以让 AI 对照要点查漏，不打分）；卡片盒（一张卡片一个观点，`[[标题]]` 链接到另一张，自动出反向链接，可以让 AI 找相关卡片、跨书的也会标出来）；内容地图 MOC（按章自动起草一份，列出本章知识点、相关卡片和前置关系，再自己改）。辅导者能看不能改；画像“习惯”页多了笔记习惯（各类数量、卡片是否只讲一个观点、链接密度、跨书关联）
- 前端：书架（含今日计划、今日复习、记忆宫殿、我的笔记入口）、学习目标设置、今日计划与番茄钟、按章展示的知识地图、知识点小测、入门诊断和报告、翻卡复习、费曼讲解、三种练习、延时复测

**AI**

图谱抽取、出题、费曼评分、OCR、记忆宫殿画面、相关笔记推荐都走 `AiProvider` 接口，有三个实现，用 `LEARNMAP_AI_PROVIDER` 切换。提示词和结果清洗规则各实现共用：

- `stub`（默认）：离线假实现，不调用任何模型。每个小节抽成一个知识点、同章按顺序串前置、每个节点出一道判断题和一道填空题，只用来把链路跑通；不支持 OCR（图片、扫描版 PDF、手写讲解会提示不支持）。
- `claude`：用 Claude（Anthropic 官方 Java SDK，默认模型 `claude-opus-5`）。抽取、出题、评分用结构化输出，结果再按业务规则清洗：题型只留能自动判分的、选择题答案必须是选项之一、关系两端必须是已有知识点。模型拒答时默认由服务端换模型重试（`LEARNMAP_AI_FALLBACKS=false` 可关）。

```bash
export LEARNMAP_AI_PROVIDER=claude
export LEARNMAP_AI_API_KEY=你的 Anthropic API key   # 不要写进代码或配置文件
export LEARNMAP_AI_MODEL=claude-opus-5               # 可选
```

- `deepseek`：用 DeepSeek（OpenAI 兼容的 chat/completions 接口 + JSON 输出模式，默认模型 `deepseek-chat`，默认地址 `https://api.deepseek.com`）。DeepSeek 的接口不收图片，所以**不支持 OCR**：照片、扫描版 PDF、手写讲解会提示不支持，文字版的书没有影响。

```bash
export LEARNMAP_AI_PROVIDER=deepseek
export LEARNMAP_AI_API_KEY=你的 DeepSeek API key    # 也认 DEEPSEEK_API_KEY；不要写进代码或配置文件
export LEARNMAP_AI_MODEL=deepseek-chat               # 可选
export LEARNMAP_AI_BASE_URL=https://api.deepseek.com # 可选，换成其他 OpenAI 兼容地址
```

调用失败（key 不对、余额不足、限流、服务出错）时接口返回 502 和原因。`ClaudeAiProviderTest.liveCall` 和 `DeepSeekAiProviderTest.liveCall` 只在 `LEARNMAP_AI_PROVIDER` 选了对应模型并设置了 `LEARNMAP_AI_API_KEY` 时真实调用一次，CI 里不跑。
