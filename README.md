# 知图 LearnMap

把任何一本书变成一张可学习的知识地图，按学习者选择的学习方式生成学习计划，用测试数据持续更新学习者画像，并告诉他下一步学什么、怎么学。

产品方案见项目文件 `product-design/learnmap-product-design-v2.md`。当前在做 **Phase 1a 核心闭环**：书 → 图谱 → 诊断 → 5 种学习方式 → 计划 → 画像 → 辅导者 Dashboard，分多个 PR 逐步交付。

## 目录

| 目录 | 内容 |
|---|---|
| `backend/` | Spring Boot 3 / Java 21 模块化单体，MySQL 8（本地开发可用内存 H2），Flyway 管理表结构 |
| `frontend/` | uni-app（Vue 3），H5 / 微信小程序 / App 一套代码 |

后端按业务分包：`user`（角色、辅导者绑定）、`book`（导入、目录解析、原文块）、`graph`（书本图谱、学习者副本、修正）、`question`（题库、一题多解）、`evidence`（作答 → 证据）、`mastery`（掌握度规则引擎）、`diagnostic`（入门诊断）、`card`（复习卡片 + FSRS）、`practice`（刻意 / 交错 / 第一性原理）、`feynman`、`retest`（延时复测）、`plan`（学习目标、计划、番茄钟）、`profile`（五张画像）、`flag`（辅导者 / 系统对节点的标记）、`tutor`（辅导者 Dashboard）、`ai`（AI 提供方接口）。

## 本地运行

需要 JDK 21、Maven 3.9、Node 18+。

```bash
# 后端：默认 dev 模式，用内存数据库，启动时自动导入演示账号和一本示例书
cd backend
mvn spring-boot:run

# 前端：H5 开发模式，/api 自动转发到 localhost:8080
cd frontend
npm install
npm run dev:h5
```

打开 http://localhost:5173 ，点“学习者 小明” → 打开示例书 → 做入门诊断，看诊断报告 → 回到知识地图看点亮情况；首页的“今日复习”可以翻卡片。

演示账号：运维 id=1、辅导者（王老师）id=2、学习者（小明）id=3。登录还没做，接口用请求头 `X-User-Id` 表示当前用户。

使用 MySQL：

```bash
docker compose up -d mysql
cd backend && mvn spring-boot:run -Dspring-boot.run.profiles=mysql
```

测试：`cd backend && mvn verify`。

## 现在能跑什么、什么还是占位

**已经能跑**
- 三种角色（学习者 / 辅导者 / 运维），辅导者绑定名下学习者，书的可见范围按方案 2.5 执行
- 上传 TXT / Markdown 书：按标题解析出 章 → 节 → 小节，切原文块，生成书本图谱和题目
- 校对规则：学习者上传的直接发布（标“未校对”）；辅导者 / 运维可以选“先校对再发布”
- 每个学习者一份图谱副本，互不影响；学习者可以删节点、标记“这条前置关系不对”
- 作答 → 证据 → 掌握度：一题多解按实际用的解法记分，分步作答只扣出错那一步的知识点；未校对节点 Confidence 上限 0.6
- 入门诊断三轮：广度扫描（全书均匀抽 ≤20 题）→ 定向诊断（从错题沿前置往下找 ≤3 层、≤15 题）→ 验证（对疑似根因再出一题，≤10 题）；报告分“疑似根因 / 受前置影响 / 建议再观察 / 已经会了”，根因按影响的后续知识点数排序
- 间隔重复 + 主动回忆：分配书时每个节点自动生成一张卡片，翻面后自评“忘了 / 困难 / 记得 / 轻松”，用 FSRS-4.5 默认参数排下次复习；每次复习都写成证据
- 费曼讲解：打字或拍手写讲解（照片走 OCR），AI 对照要点给出讲到 / 讲漏 / 讲错和追问，可以接着回答追问；低分或有错误陈述的交辅导者复核
- 刻意练习：根因节点先出 3 道验证题，没全对就做 5 道专项练习（含掌握度低的前置），3 天后复验
- 交错练习：至少 3 个掌握度 ≥ 50% 的节点才开始，优先混易混淆的节点，其次同章同类型，8 道打乱顺序，统计“方法选错”
- 第一性原理：选一个目标知识点，数据不足的先探测，不会的沿前置递归往下拆（最多 4 层、超过 15 个提示离基础较远，共享前置只查一次，遇到环停下），再从最底层往上逐个“讲解 + 3 道题”补回来，两轮不过标记给辅导者，最后回到目标做 2 道题
- 延时复测：学会的节点自动安排 3 / 7 / 21 天复测，记下当时用的学习方式
- 学习目标与计划：学习者或辅导者设目标（整本书 / 指定章 / 只补薄弱点、截止日期、工作日和周末各多少分钟、主风格、节奏）。计划先放到期卡片和复测，再按前置关系拓扑排序、薄弱且影响面大的先学，按节点类型 × 主风格配活动（事实：初学 + 小测；概念 / 原理：费曼 + 小测；方法：刻意练习；综合：第一性原理），每 3 天插一次交错练习，每项都写明理由；按番茄钟 25 分钟 / 碎片 10 分钟 / 整块切块；只排 14 天，学不完会提示。每天凌晨 3 点按最新掌握度重排，也能手动重排，做过的任务保留
- 番茄钟：前端计时，开始 / 结束 / 是否坚持完 / 被打断几次记到后端，供行为画像使用
- 五张画像（规则 + 统计，不用 AI）：知识（每章每个节点的掌握度，热力格子）、能力（按题目标注的能力算正确率，费曼平均分算“表达”，答前自评和实际对错的偏差，常用解法）、错误（各错因占比）、学习方式（回放掌握度引擎算每种方式在每类节点上“每 10 分钟提升多少”，加上延时复测保持率和完成率，给出“概念类你用费曼效果最好”这类建议）、学习行为（连续天数、计划完成率、拖延、番茄钟坚持率和打断次数、常学时段）。学习者自己只看点亮数、连续天数和最适合的方式
- 辅导者 Dashboard：名下学习者一览（点亮数、薄弱数、连续天数、计划完成率、提醒）；点进去看五张画像；点任意节点看“为什么不会”——最近作答、前置链上每层的掌握情况、最可能的根因；可以标“诊断不对，他其实会”（马上安排一次复测验证）或“确实不会”；复核低分的费曼讲解（复核分也记成证据）；第一性原理补了两轮还卡住的节点自动提醒辅导者；可以给学习者分配书、设学习目标、看计划
- 运维：汇总被标“诊断不对”最多的书本图谱节点，用来发现题目或图谱的问题
- 前端：书架（含今日计划、今日复习入口）、学习目标设置、今日计划与番茄钟、按章展示的知识地图、知识点小测、入门诊断和报告、翻卡复习、费曼讲解、三种练习、延时复测

**还是占位（stub）**
- **AI**（按计划最后对接）：图谱抽取、出题、费曼评分、OCR 都走 `AiProvider` 接口，目前只有离线假实现 `StubAiProvider`——每个小节抽成一个知识点、同章按顺序串前置、每个节点出一道判断题。接真实模型需要 API key，通过环境变量 `LEARNMAP_AI_PROVIDER` / `LEARNMAP_AI_API_KEY` / `LEARNMAP_AI_MODEL` 配置，不写进代码
- **登录**：用 `X-User-Id` 请求头代替
- **EPUB / PDF / Word / 图片（OCR）导入**：会直接提示“还在开发中”，计划由单独的 Python 导入流水线服务处理
